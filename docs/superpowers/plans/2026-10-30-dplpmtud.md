# DPLPMTUD Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. **This proposal is not approved for execution; task 0 is a mandatory owner/protocol gate.**

**Goal:** Discover a usable per-direction UDP payload size with ICMP blocked, then deliver fitting inner packets or explicit source feedback.

**Architecture:** A pure event-driven controller emits bounded actions. Primary tier E supplies authenticated probe/ACK discovery between two extension-capable BoringTun endpoints, matching the owner's 2026-10-30 deployment priority. Secondary tiers R/I use configured in-tunnel feedback through unchanged WG/AWG peers; L supplies local limits/hints without a delivery claim. Device/FFI adapters supply path identity, qualified socket behavior, send completion and inner traffic handling.

**Tech Stack:** Existing Rust 2018 crate, Rust 1.75 core/FFI compatibility, existing cryptographic/session facilities, additive C ABI; Linux CLI first if the owner accepts that scope.

**Spec:** [DPLPMTUD design proposal](../specs/2026-10-30-dplpmtud-design.md). Read it before this plan. Baseline: `ea0f5f85946ed69fcb0ad2f4dadfb46a672e1c0d`.

## Global constraints

- Documentation stage only until remaining secondary-adapter/platform/IPv6 decisions and task-0 wire/ABI contracts are approved. The primary two-BoringTun deployment assumption is settled; protocol implementation is not approved. Names/interfaces below are proposed, not an existing API.
- No assumption of ACK support in vanilla WG/AWG; no generic keepalive/send-success/inbound-size confirmation.
- Core has no OS socket, routing or TUN dependencies; keep Rust 1.75 and Windows 7 core/FFI builds.
- Store full BoringTun UDP payload size U; account for all headers/proxies exactly once. Zero is not a discovered limit.
- No fragmented probes, application retransmission engine, key/counter rollback or global TUN MTU reduction.
- Existing calls preserve behavior when discovery is disabled; new control behavior requires per-peer opt-in and authenticated capability confirmation.
- ICMP hints are optional. Do not make a later ICMP/error-queue adapter a dependency of the blocked-ICMP acceptance test.
- Product name, old BoringTun version, handshake or generic traffic cannot substitute for E capability negotiation. R/I require explicit targets and their own qualified matched feedback; L has no confirmed-size field.
- Preferred/required selection and tier changes follow the spec: visible fallback reasons, no stale evidence relabeling, no automatic target discovery and no same-path cap increase on downgrade.
- Each implementation PR needs its own release-intent decision under the repository policy; the documentation's `bump: none` never covers product changes.

## Review focus

1. A forged/replayed ACK races endpoint adoption or rekey: it must not promote the new path (tasks 1, 2, 4).
2. A large "probe" is fragmented, truncated, or stripped by a proxy: it must not produce a confirmed size (tasks 2, 4, 6).
3. A second peer uses the same listener during a budget/path transition: it must retain its independent limit and session (tasks 1, 4).
4. Inner IPv6 is 1280 bytes but only 1200 bytes fit: the host must receive an explicit unsupported-path state, not a false success (tasks 3, 5, 6).
5. A full-size probe/ACK is lost while small data continues: confirmation must still expire and recovery must be bounded (tasks 1, 6).

Proposed shared interface vocabulary (freeze in task 0; do not independently rename in later tasks):

```rust
struct UdpPayloadBytes(u32);
struct InnerIpBytes(u32);
struct PathEpoch(u64);
struct SessionGeneration(u64);
struct ProbeId { epoch_nonce: [u8; 16], sequence: u64 }
struct SendHandle(u64);
struct MonotonicMillis(u64);

impl Controller {
    fn new(config: Config, epoch_nonce: [u8; 16]) -> Result<Self, ConfigError>;
    fn on_event(&mut self, now: MonotonicMillis, event: Event) -> Actions;
    fn status(&self) -> Status;
    fn next_deadline(&self) -> Option<MonotonicMillis>;
}
```

`Event` variants carry path/session/wire-profile/evidence-generation identity: `PathChanged`, `CapabilityConfirmed`, `FeedbackAdapterChanged`, `Serialized`, `Sent`, `SendFailed`, `SendOutcomeUnknown`, `VerifiedAck`, `VerifiedResponderReply`, `VerifiedEchoReply`, `ValidatedSizeHint`, `TrafficActive`, `Tick`, `Disabled`. `Actions` is a bounded list: `ProbeRequest`, `BudgetChanged`, `StatusChanged`; no user-data retransmission action. `ProbeRequest` contains ID, target U, generations, tier/scope and send handle. `VerifiedAck` is E-only and contains echoed identity/size and observed U. The R/I variants contain validated request identity and locally mapped sent U, with observed U absent. Only the appropriate authenticated/matching library adapter constructs those evidence events, never arbitrary host assertions. Define the constructor and target/credential lifetime boundaries before exposing them to FFI. `Status` separates confirmed, operational, configured and hinted values and includes the spec's evidence scope/downgrade fields.

## Integration matrix and objective acceptance (by tier)

Primary E timings below use fake/controlled time, the default 16-second T, no scheduler deferral, and RTT <=100 ms unless stated. Record actual U, outer packet length, fragments, selected tier/evidence scope, state changes and source-visible feedback. Real-network results also report latency and global-budget deferral separately. R inherits these timing goals only when its qualified service/return path satisfies the same assumptions; I has conservative request/response results and no independent-direction convergence promise. Task 6 gates E; task 7 reruns applicable common tests plus the secondary rows before claiming those tiers supported.

| Case | Required outcome |
| --- | --- |
| Direct IPv4/IPv6 with all outer ICMP blocked; outer MTUs 1500, 1420, 1280 | Base confirms; search converges without PTB to within 7 bytes of the admissible UDP ceiling. No ordinary emitted datagram exceeds the current operational cap. |
| Search bound width <=512 bytes | At most `2 + 5 * (ceil(log2(512 / 8)) + 1)` transmitted probe attempts including reconfirmations; completion <= that bound times `(T + 1 s + RTT)` in a loss-free size-drop model. Count accepted sends, not polls. |
| Established outer MTU falls 1500 ->1280, ICMP blocked | Active confirmation detects failure and clamps to base within 30 s + 10% jitter + 3T + scheduler tick (<=82 s at 1 s tick); base confirmation/research follows. Existing lost user traffic is not retransmitted. |
| MTU rises 1280 ->1500 | Start upward search no later than 660 s + scheduler tick after the last completed search; failed bound does not persist forever. |
| Forward 1500 / reverse 1280 and the opposite; one-way application data | Discover independent directions using small ACKs. No need for reverse application traffic or a same-size echo reply. |
| ACK path drops everything | Never claim confirmed size from unrelated inbound data or local sends. Reach fallback/unavailable state with bounded retries and visible cause. |
| Scripted 10% independent loss, two-packet bursts, reordering, duplicates | Single/double isolated probe loss does not reduce a confirmed size; no false promotion, no descent below configured floor, no storm. Stable loss-free period restores search within the stated raise interval. |
| Replayed/mismatched ACK, old session, delayed reply after roaming | No change to new-path state or any other peer; malformed/control traffic never reaches TUN. |
| IPv4 DF off, IPv6 source fragments, GSO splitting, SOCKS relay reassembly | Adapter cannot claim qualified discovery; capture failure/unsupported state prevents promotion. Legacy configured mode remains clearly distinct. |
| EMSGSIZE, stale route PMTU cache, send queue full, unknown completion | Accurate local error provenance; no successful-delivery claim. Cache does not permanently prevent upward reprobes; backpressure is not counted as network loss. |
| AWG plain/v1-v3.1 profiles, S4 extremes, padding/trailers, small handshake cap | Exact admitted U; no optional-byte overflow, no nonce rollback, explicit incompatible bootstrap status. Reject unrepresentable configuration before loop. |
| Inner IPv4 DF=1/0 and IPv6 | Valid source-visible feedback/inner fragmentation; 1280-byte IPv6 fits or reports unsupported path. Oversize packet is not silently counted as delivered. |
| Stock WG/AWG and old BoringTun, E capability absent | Existing interoperability passes in disabled/preferred configuration; no padded E probe. Preferred uses only explicitly configured R/I or L with provenance; required blocks peer data. Product name never upgrades the tier. |
| E peers with supported/unsupported versions, disabled extension or lost capability ACK | Negotiate only a supported authenticated version; distinguish no-common-version from unconfirmed timeout. Same-path fallback cannot raise the cap; late old-tier replies have no effect. |
| R service at unchanged peer host; forward 1500 / reverse 1280 | Small ACK confirms qualified forward request delivery without a new tunnel wire format; no invented remote UDP-length observation. Missing service/authentication stays unconfirmed. |
| I existing echo: forward 1500 / reverse 1280, and reverse echo blocked | Full matching success confirms only the actual mapped forward lower bound. Failed large echoes do not establish a forward upper bound; blocked replies give no confirmation. |
| Outer PTB blocked, inner echo allowed; then inner echo blocked too | I may work in the first case only if all matching/mapping conditions pass; E still works in both cases. L never claims discovery from silence. |
| R/I responder beyond peer; inner segment drops large requests | Status includes `tunnel_plus_responder_path`; failure cannot identify outer PMTU. No arbitrary responder discovery and no reuse of endpoint-only evidence. |
| L only: blocked PTB, no responder, large local sends accepted or failed | Configured/local/hinted operational cap and explicit unknown delivery. No confirmed U, no claimed ICMP-black-hole recovery, and no invented MTU from bare EMSGSIZE. |
| >=1000 peers, adversarial authenticated probe input | Pending state remains O(peers), one outstanding per peer, exact rate/byte budgets respected, fair scheduler, bounded logs; no ACK amplification. |
| Linux CLI, macOS CLI, Windows DLL host variants | Per-platform real-socket proof required to mark supported. Unsupported adapters fail explicit activation checks and preserve existing mode. |

The search-attempt bound assumes no rekey/roam/local cancellation, timely timer processing and successful lower-size confirmations. Each rejected candidate uses three failed sends. With 30-second confirmation spacing, 16-second timeout and <=100 ms RTT, allowing the accepted attempt to finish (rather than canceling at confirmation-due) inserts at most two lower-size confirmations including the final reconfirmation: at most five sends per candidate. A width of 512 on an 8-byte grid needs at most seven candidates including the initial maximum, plus initial/base overhead. The deterministic trace must prove this bound; other timing profiles, path changes and scheduler deferral get separate measured budgets rather than this guarantee.
