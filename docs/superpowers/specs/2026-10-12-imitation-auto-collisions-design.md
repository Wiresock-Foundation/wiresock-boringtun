## 1. Root cause (code-referenced)

Both receive doors classify AmneziaWG shapes first and offer a datagram to the imitation detector only when it fits no packet kind:

- device listener: probe_reply.rs:162-165 (`classify`) returns `Ingress::Wireguard` for any candidate; imitation_auto.rs:45-61 observes only non-WireGuard ingress; device/mod.rs:1786 drops `Refused | NotOurs`.
- core Tunn: noise/mod.rs:1022-1027 observes only with an empty candidate list; `Refused(e)` becomes `TunnResult::Err(e)` at :1048.

A transport reading fits whenever `wire_len >= S4 + 32` and the unmasked u32 at offset S4 is in H4 (amnezia.rs:1746-1800). With S4 = 36 the bytes at 36..40 of a 100-108 byte STUN Binding Request lie in USERNAME, drawn once per burst (stun.rs:229) and present in both requests, so both recognizable datagrams of a burst collide together (identical `hIew`, `inph`, `hrom` in both requests of every recorded run). The transport trial fails (`WrongIndex` on the device, `NoCurrentSession` in a Tunn), the outcome is `Refused`, the datagram is never detected, the initiation finds no hint, STUN S-junk is never a complete Binding Request so self-detection cannot help, and `commit_with_imitation` (mod.rs:1295-1345) leaves the peer unresolved.

Verified on the recorded sequence: datagrams #1 (104 B) and #2 (108 B) carry tag 2003126632 at offset 36 and are transport candidates under H4 1917290954-2017290953 only; #3-#5 are not valid Binding Requests and are candidates under neither H4. Real-client-4 (both recognizable datagrams colliding) gave 0/16 shaped output with 15/15 pings; real-client-2/-3 were rescued by a Jc junk datagram that was a valid Binding Request with no candidate. Per-datagram odds must not be multiplied: the two requests share token bytes.

## 2. Alternatives, recommendation, residual limitations

- A. Client-side avoidance: needs every imitating client upgraded (released BoringTun CLI/JNI builds, WireSock netlib clients), so it does not meet the goal; separate low-priority follow-up at most.
- B. Detect before shapes: rejected; DNS/SIP conforming WireGuard datagrams detect (detect.rs:25-32) and would be hinted on and SERVFAILed.
- C. Hint on any `TunnResult::Err`: rejected; reinterprets accepted packets whose commit failed.
- D. Adopted: in Auto mode, after ordinary candidate processing finishes, inspect the original datagram once for imitation evidence only when the final disposition is an ordinary refusal and every candidate refusal satisfies the eligibility policy in section 3. Preserve the original return error. Fallback neither sends replies nor commits, retries or selects a peer mode.
- E. STUN initiation self-evidence (the S1 junk is a complete Binding Request when 24 <= S1 <= 148 and S1 % 4 == 0): deferred; it changes the detector contract.

Recovery statement. D recovers recognizable prelude collisions rejected through allowlisted MAC, authentication, routing or missing-state failures. Recovery requires a matching source (full SocketAddr on the shared listener, source IP in the core slot), evidence retained until a successful authenticated initiation commit for an unresolved peer, and a protocol permitted by header-protection policy. It does not cover cookie or load dispositions, conflicting earlier hints at the same source, expiry, eviction, device clearing, or replacement of the core slot by a different source. Timestamp and counter rejection outcomes, local failures, and all other non-allowlisted errors veto fallback. Replay provenance itself is not detected: replay-derived datagrams rejected with an allowlisted routing or missing-state error may still supply evidence. Eligibility requires every candidate failure to be allowlisted. Valid MAC1 alone neither permits nor excludes fallback. Colliding probes remain unanswered, so a DPI observer sees unanswered Binding Requests exactly as with probe replies disabled. QUIC: syntactically recognizable long headers below 1200 bytes can still supply hints (detect.rs:139); the 1200-byte floor belongs to Version Negotiation reply generation.

## 3. Eligibility policy, representation, state model, exposure

"Eligible" permits detection and ordinary hint retention under the existing `observe` rules; it never means selection.

| Receive disposition | Fallback | Reason |
|---|---|---|
| No candidates | existing path | detection and probe policy unchanged |
| `Accepted`, including a later commit failure | no | an accepted packet is never reinterpreted |
| `Cookie` or `Refused(UnderLoad)` | no | cookie/load disposition preserved |
| `InvalidMac` | yes* | mac1 failed before the trial |
| `WrongKey` | yes* | core: claimed static rejected before timestamp authentication; anonymous ingress: static extraction failed or peer unknown |
| `WrongIndex`, `NoCurrentSession` | yes* | routing or session lookup established nothing |
| `UnexpectedPacket` | yes* | no matching in-flight state before cryptographic verification |
| `InvalidAeadTag` | yes* | cryptographic verification of that reading failed |
| `WrongTai64nTimestamp`, `InvalidTai64nTimestamp` | no | timestamp validation follows decryption |
| `DuplicateCounter`, `InvalidCounter` | no | replay-window refusals excluded conservatively |
| `DestinationBufferTooSmall` | no | local inability to complete verification (response at mod.rs:1225, transport at session.rs:281) |
| `InvalidPacket`, `WrongPacketType`, `IncorrectPacketLength` and every other error | no | conservative default |

\* only when every candidate failure is allowlisted and the final outcome is ordinary refusal. Candidate order, later acceptance, cookie/load precedence and the first reported error are unchanged; an early allowlisted error must not hide a later veto, and a veto must not stop candidate processing.

Representation (internal only, no public error or ABI change):

- `noise/imitation/auto.rs`: `pub(crate) fn allows_imitation_hint(error: &WireGuardError) -> bool`; the six allowed variants return true, `_ => false`. The name states policy, not authentication status.
- `noise/inbound.rs`: `pub(crate) struct Refusal { pub(crate) error: WireGuardError, pub(crate) allows_imitation_hint: bool }`; `Inbound::Refused(Refusal)`. In `receive`, a local flag starts true and is ANDed with `allows_imitation_hint(&e)` at every refusal site: `candidate_message` returning `None` (InvalidPacket, veto), each parse error (veto), `BadMac` (InvalidMac, allowed), every trial `Err(e)`. `refusal.get_or_insert(e)` is unchanged; the `UnderLoad` return sets the flag false.
- `Inbound::Refused` match inventory (complete): device/mod.rs:1786 (production door, below); noise/mod.rs:1048 (core hook, below); inbound.rs:48, :146, :149 (definition and returns); inbound.rs:638 test `(None, Refused(UnderLoad))` -> `Refused(Refusal { error: UnderLoad, .. })`; disable_cookies_tests.rs:697 `Refused(WireGuardError::InvalidAeadTag)` -> `Refused(Refusal { error: InvalidAeadTag, allows_imitation_hint: true })`, retaining its `tried == 1`, `load_events() == 0` and armed-limiter `Cookie` assertions.

Shared listener cache (imitation_auto.rs:63-79): keyed by full `SocketAddr`; first live hint per source retained without refresh; expiry 30 s; oldest evicted at 1024. No learned-peer check: evidence can be stored at an already learned peer's endpoint; selection ignores it (`previous.is_some()`) and the production handler discards it after a selected initiation (device/mod.rs:1828), not `commit_anonymous`. Core slot (auto.rs:38-57): one `Option<(Option<IpAddr>, Hint)>`; a different source replaces the slot even while the previous hint is live; the same source keeps its first live hint; `None` is one source value with no address separation (FFI uses it). Lifecycle: an authenticated roam or configured endpoint change discards pending tunnel evidence and keeps the learned mode; peer removal clears the device cache; the retired-callback lifetime check (device/mod.rs:2028) runs under the peer lock before `decapsulate`, so the fallback must stay after it.

Exposure. Camouflage evidence is source-bound and unauthenticated. With header protection disabled, an attacker can wrap a replayed canonical message in an `INVITE ` prefix; if that datagram is refused with an allowlisted error (for example `WrongIndex` or `NoCurrentSession` after the session it belonged to is gone) it detects as SIP and can select SIP for an unresolved peer's later genuine initiation. Timestamp and counter rejection outcomes, local failures and all other non-allowlisted errors veto fallback, but replay provenance itself is not detected. Fallback therefore adds eligible traffic and poisoning opportunities within the existing documented model: a source-spoofing attacker already has the cheaper plain-prelude route, and neither a hint nor its protocol is proof that the evidence came from the peer whose initiation consumes it. Stronger binding is out of scope. No new reflection. Memory unchanged. CPU: one bounded `detect` per eligible refusal; under cookie/load dispositions no new work.
