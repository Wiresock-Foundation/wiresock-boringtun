WireSock BoringTun 0.8.0 establishes an explicit version line for the WireSock
fork of Cloudflare BoringTun. It brings together the AmneziaWG and WireSock
extensions, embedding APIs, reliability fixes and security hardening accumulated
while the packages still reported 0.7.1.

**Already running build b114?** The runtime behavior below was already present
in b114 or earlier builds. Since b114, this release changes package versions,
release notes and release automation; it does not introduce another tunnel
engine or a new protocol configuration. The generated source comparison at the
end covers that narrower release-engineering change.

## New

### Protocols and traffic shaping accumulated since the original 0.7.1

- **AmneziaWG configuration on both client and server paths:** S1–S4 packet
  prefixes, H1–H4 message tags/ranges and Jc/Jmin/Jmax pre-handshake junk. The
  fork also implements AmneziaWG 3.0 header protection, optional content
  padding and tunable handshake/session timers, plus the 3.1 `RandomTrailers`
  and `DisableCookies` options. Matching peers must agree on the required
  protocol parameters; these extensions do not make arbitrary obfuscated
  profiles compatible with a plain WireGuard peer.
  ([Initial integration #8](https://github.com/Wiresock-Foundation/wiresock-boringtun/pull/8),
  [header protection #33](https://github.com/Wiresock-Foundation/wiresock-boringtun/pull/33),
  [padding #35](https://github.com/Wiresock-Foundation/wiresock-boringtun/pull/35),
  [timers #38](https://github.com/Wiresock-Foundation/wiresock-boringtun/pull/38),
  [3.1 options #52](https://github.com/Wiresock-Foundation/wiresock-boringtun/pull/52),
  [#53](https://github.com/Wiresock-Foundation/wiresock-boringtun/pull/53))
- **WireSock protocol imitation:** DNS, QUIC, SIP or STUN framing replaces random
  prefix bytes with protocol-shaped traffic. Fixed modes also emit standalone
  cover sequences before Jc and the handshake; QUIC offers browser-shaped
  Initial profiles. The optional probe responder
  supplies supported DNS, QUIC Version Negotiation and STUN replies within an
  aggregate unauthenticated reply budget. SIP probes and QUIC v1/v2 Initials
  remain unanswered. This improves plausibility; it is not a guarantee against
  traffic analysis or an informed active probe.
- **Per-peer server auto imitation:** `--imitate-protocol auto` (or
  `WG_IMITATE_PROTOCOL=auto`) learns each peer's imitation mode from a temporary
  source-endpoint hint and an authenticated handshake. Unresolved peers use
  random padding. Auto selects imitation only, not keys or AmneziaWG settings;
  deliver the client's initial camouflage datagrams to the server. It does not
  send standalone imitation or Jc bursts, and the CLI rejects
  `--imitate-domain` with auto. Fixed modes remain available. Auto can now also
  learn from certain refused datagrams that happen to match an AmneziaWG
  packet shape, without replying to those datagrams as probes.
  ([#78](https://github.com/Wiresock-Foundation/wiresock-boringtun/pull/78),
  [#82](https://github.com/Wiresock-Foundation/wiresock-boringtun/pull/82))
- **Randomized persistent keepalive:** Rust, C and UAPI callers can configure
  a range such as `25-35`. Each rearm chooses a fresh interval; fixed intervals
  keep their previous meaning. A later scalar setting replaces the range.
  `0`/`0-0` disables it, `0-30` draws from 1–30 seconds, upper bounds saturate
  at 65535 seconds, and inverted ranges are refused without changing state.
  ([#104](https://github.com/Wiresock-Foundation/wiresock-boringtun/pull/104))

### Embedding and diagnostics

- A versioned C `wireguard_awg_params` structure and the JNI AWG constructor
  expose the extended configuration without a new constructor for each option.
  Embedders can refresh the MTU used to clamp optional padding.
  ([#39](https://github.com/Wiresock-Foundation/wiresock-boringtun/pull/39),
  [#41](https://github.com/Wiresock-Foundation/wiresock-boringtun/pull/41),
  [#58](https://github.com/Wiresock-Foundation/wiresock-boringtun/pull/58))
- C `wireguard_*_ex` operations expose per-call packet/event/state metadata and
  optional output budgets. They let callers distinguish control traffic from
  transport data and integrate packet sizing and burst scheduling. Zero budgets
  retain legacy behavior. A finite transport budget can discard queued packets
  whose mandatory frame cannot fit; callers receive a queue-drop event.
  ([#91](https://github.com/Wiresock-Foundation/wiresock-boringtun/pull/91))
- Rust `Tunn::decapsulate_from` accepts a full source socket address;
  `decapsulate_from_with_metadata` and `AuthenticatedPacketKind` expose receive
  classification. Bounded device UDP diagnostics help distinguish peer route
  problems from device failures.
  ([#90](https://github.com/Wiresock-Foundation/wiresock-boringtun/pull/90),
  [#75](https://github.com/Wiresock-Foundation/wiresock-boringtun/pull/75))

## Fixed

### Control plane, peer lifetime and sockets

- **Slow UAPI clients no longer block packet handling.** Partial requests are
  buffered, frames end with a blank line, and inherited Linux control streams
  support ordered repeated/pipelined requests. Ordinary socket clients receive
  one response per connection. Limits are 32 simultaneous accepted clients,
  1 MiB per request and 4 MiB per response. Request/response deadlines are an
  absolute five seconds; trickle traffic does not extend them. An ordinary
  stalled client is closed without stopping the device.
  ([#112](https://github.com/Wiresock-Foundation/wiresock-boringtun/pull/112))
- **Peer replacement releases old connected endpoints.** Replacing all peers
  detaches their UDP endpoints before clearing the maps. Event-loop reclamation
  is asynchronous, as with individual removal and roaming; replacement does
  not promise lossless traffic while packets are in flight.
  ([#111](https://github.com/Wiresock-Foundation/wiresock-boringtun/pull/111))
- Peer updates and endpoint errors return errors instead of aborting the daemon.
  Listener rebinding is transactional; successful rebinds preserve the stored
  fwmark, and failed multi-socket mark updates attempt rollback. Runtime UAPI
  failures preserve their errno. Pending handshakes survive unrelated live AWG
  configuration changes. MTU handling uses an inherited TUN's actual MTU and
  avoids stale-MTU read truncation; Darwin MTU-query error paths close their fd.
- IPv4-only hosts can start when IPv6 socket creation reports an unsupported
  family. Other IPv6 failures still fail the bind. An IPv6 peer without a usable
  IPv6 listener reports a per-peer route error; a later port rebind can acquire
  IPv6. Linux IPv4-mapped IPv6 endpoints use and report their IPv4 form.
  UAPI paths under `/var/run/wireguard/` and `/var/run/amneziawg/` no longer
  contain doubled separators.
  ([#86](https://github.com/Wiresock-Foundation/wiresock-boringtun/pull/86))

### Timers, queues and packet handling

- Keepalive and handshake timers now follow the reference state machine more
  closely: authenticated traffic postpones persistent keepalives, enabling a
  keepalive after expiry can restart the handshake, and handshake retry timing
  includes jitter. Backward clock steps no longer underflow timer arithmetic
  and abort C/JNI callers. A buffer-refused keepalive remains owed for retry.
- The replay window grows from 1024 to 8192 counters, tolerating more legitimate
  packet reordering at a cost of about 7 KiB per tunnel.
  ([#85](https://github.com/Wiresock-Foundation/wiresock-boringtun/pull/85),
  [#87](https://github.com/Wiresock-Foundation/wiresock-boringtun/pull/87))
- No-session writes that return an error no longer also enqueue their input,
  preventing duplicate delivery on retry. A full pending queue reports
  `PacketQueueFull`; draining preserves a packet that is merely too large for
  the destination buffer. Pending camouflage bursts no longer suspend absolute
  handshake/key-lifetime limits. Short destination buffers return errors, and
  padded keepalives are accepted.
- Ambiguous datagrams are tried against eligible packet interpretations before
  committing the authenticated one. Header-protected/imitation framing avoids
  collisions with plain control packets. Invalid IPv4 header lengths are
  rejected before delivery; fragment and checksum handling remains with the
  receiving network stack.

## Security

- **Linux UDP port ownership is separated by UID.** Listeners and connected
  peers use `SO_REUSEPORT` without `SO_REUSEADDR`; a different unprivileged UID
  cannot join their port. Same-UID processes can still share it. IPv6 sockets are
  IPv6-only, keeping address-family reuse groups separate. The CLI prepares
  TUN/UAPI before dropping privileges, then creates UDP sockets and workers
  under the final UID. Missing reuse-port support and queue/worker setup
  failures fail startup rather than silently weakening this behavior. Other
  platforms retain their existing sharing options.
  ([#113](https://github.com/Wiresock-Foundation/wiresock-boringtun/pull/113))
- Cookie replies no longer roam peer endpoints, count as received traffic for
  timers, or validate repeatedly for the same sent handshake. Reject-After-
  Messages is enforced in both directions to prevent nonce reuse even without
  timer polling. The earlier Rekey-After-Messages threshold remains unimplemented.
  ([#83](https://github.com/Wiresock-Foundation/wiresock-boringtun/pull/83))
- Handshake admission accounts per source as well as globally, and all device
  peers share the device limiter. Cookies bind to address and UDP port when a
  full endpoint is available. NAT neighbours share the address allowance;
  concurrent admission and fixed-size hash tables make it approximate. Legacy
  address-only receive APIs keep address-only cookie binding; source-less C/JNI
  calls cannot issue cookies and refuse under-load handshakes.
  ([#84](https://github.com/Wiresock-Foundation/wiresock-boringtun/pull/84))
- Zero-length UDP packets on connected sockets are ignored, preventing network
  traffic from invoking the API's intentional queue-drain operation. Invalid
  encoded keys are rejected instead of becoming zero keys. Unauthenticated
  probe/cookie replies retain output-size and aggregate reply safeguards.
- JNI checks caller-provided lengths against array/direct-buffer capacity and
  rejects null tunnel handles before crossing the native boundary, preventing
  those invalid inputs from causing native overreads or aborting the JVM.
  The JNI migration also fixes JVM/FFI string leaks and preserves exceptions
  for short keys. These checks do not validate arbitrary non-null native handles.
  ([#16](https://github.com/Wiresock-Foundation/wiresock-boringtun/pull/16))
- `DisableCookies` is an explicit security tradeoff: it bypasses the under-load
  cookie defense for valid-mac1 handshakes. It is off by default. Header
  protection requires every S1-S4 prefix to be at least 12 bytes. Fixed SIP
  imitation with header protection is refused if any prefix is 31 bytes or
  longer; Auto instead declines that incompatible learned SIP mode and keeps
  random padding. DNS/STUN can carry nonce-strength warnings. Auto hints are
  camouflage metadata, not identity.

## Compatibility & upgrade notes

### Applications and configuration

- **From b114:** no protocol-profile conversion is required by this
  release-engineering change. Packages and the CLI now report 0.8.0. Rebuild
  linked applications and select the matching archive when adopting the new
  version; installers pinned to an older technical tag remain pinned.
- **From original upstream 0.7.1:** review the fork's extended API/configuration,
  and configure matching peer keys, S/H values and any enabled AWG extensions.
  Default/plain WireGuard operation remains available. Auto imitation does not
  infer those protocol settings. Use `--probe-reply-rate 0` to disable probe
  replies while retaining auto detection.
- **Rust source compatibility:** exhaustive `WireGuardError` matches need to
  handle `PacketQueueFull`, `OutputBudgetExceeded` and `InvalidPacketInfo`.
  Existing error discriminants 0–16 are unchanged; new codes are 17–19. The
  `Tunn::new` constructor takes eight additional H1-H4 range-bound arguments
  and returns a `Result` that callers must handle, rather than a tunnel directly.
  The low-level `parse_incoming_packet` API also accepts the fork's obfuscation
  configuration. Recompile and review low-level parser/obfuscation callers;
  0.8.0 is a minor version specifically because the cumulative API is not an
  unchanged upstream 0.7.1 surface.
- **C/JNI:** existing result layouts and original error values are retained.
  However, the C `new_tunnel` symbol takes eight additional H1-H4 range-bound
  arguments compared with original upstream 0.7.1. Update and recompile callers
  against the matching header; this is not a drop-in shared-library replacement
  for applications compiled against that upstream constructor.
  New APIs use explicit size/version contracts; zero-initialize the AWG and
  packet-info structures and set their size as documented in the C header.
  JNI's AWG parameter byte array uses that native structure layout. For `_ex`
  calls, check the operation result and event flags together and honor output
  budgets; a received packet being accepted is not alone permission to roam.
  Rust metadata is non-exhaustive. Endpoint adoption must require peer
  authentication and a successful operation; a cookie reply is not such proof.
  JNI's existing Java constructor remains unchanged. Respect array/direct-buffer
  capacities and handle `IllegalArgumentException` from invalid lengths or
  null tunnel handles.
- **Timer profiles:** unfavorable but well-formed timer orderings are now loaded
  with a warning instead of rejected. A session may expire before renewal and
  traffic can stall until the next handshake. Review warnings; malformed zero
  duration ranges and inverted ranges remain errors.

### Supervisors, privileges and readiness

- Treat inherited Linux `--uapi-fd` as a lifecycle channel. It may idle between
  transactions indefinitely, but EOF, broken transport, a transaction timeout
  or an oversized request stops the entire device. Restart with a **fresh fd**;
  there is no replacement-fd API. Ordinary complete-request configuration
  errors remain nonfatal, as does a delivered `EOVERFLOW` response. Always check
  UAPI errno: a complete `set=1` can partially apply before a later key fails.
- Keep the socket-creating UID consistent across startup, peer upgrades and
  rebinding. `DeviceHandle::new_with_privilege_drop` changes process-wide
  credentials, even if a later startup stage fails; call it before other
  devices/threads. `DeviceHandle::new` keeps credentials unchanged. Neither
  retains extra capabilities. Startup cleanup is best-effort; the supervisor
  may need to remove UAPI paths that the final UID cannot unlink.
- **fwmark is not a startup safety gate.** Listeners initially have mark zero;
  a refused update returns an error and leaves the engine running. Rollback can
  also fail, leaving mixed marks, and `get=1` reports the last stored mark rather
  than auditing every socket. Marking still needs the appropriate Linux
  capability even with inherited TUN/UAPI fds. If routing safety depends on it,
  keep an external egress gate closed before launch and during live mark changes,
  send `fwmark=` in a separate first request, and require `errno=0` before peers
  or traffic are enabled. Keep the gate closed on error and stop/recreate the
  engine or reconcile all marks. No `--require-fwmark` mode is implemented.
  This is the documented contract, not a new fail-closed guarantee.
  ([#114](https://github.com/Wiresock-Foundation/wiresock-boringtun/pull/114))
- Use foreground mode for supervised logging. The retained `daemonize` dependency
  has a documented maintenance-status advisory exception; it does not suppress
  other advisories or establish validation of daemon mode.

### Platforms and release integrity

- CLI archives cover Linux x86_64, aarch64 and armv7 with musl, plus macOS x86_64
  and aarch64. The `device`/UAPI implementation is Unix-only; Windows builds
  provide the core library and applicable bindings, not this Unix CLI device.
  The source retains upstream NetBSD support, without a prebuilt NetBSD archive
  in this release set.
- Rust 1.75 compatibility is retained for the Windows 7 FFI build path with its
  documented compatible dependency lock preparation. This is not the toolchain
  floor for all features: JNI and release builds use newer toolchains, and the
  reviewed release recipe pins Rust 1.98.1. Platform packaging targets do not
  imply that every privileged integration test runs on every operating system;
  consult the exact source/build evidence for the relevant checks.
- Technical tag and archive naming, schema-2 signed `RELEASE.json`, checksums
  and the **seven assets** remain compatible with the existing AWG consumer.
  Verify the descriptor, archives and provenance before adoption. Full notices
  and retained upstream attribution accompany the packaged binaries.
- Automatic publication remains per meaningful merge. Maintainers explicitly
  choose `patch`, `minor` or docs/tests-only `none` in the PR; retries keep the
  same version and signed bytes. A separate serialized reconciliation chooses
  the highest eligible stable version for Latest, independent of build order.
  Historical release bodies and pinned installer references are not rewritten.
