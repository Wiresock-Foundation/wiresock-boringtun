WireSock BoringTun 0.8.0 gives the maintained fork a clear version and readable
release history. It includes the API additions, reliability fixes and security
hardening accumulated since the original 0.7.1 package version.

**Since the previous published build b114:** this release changes versioning
and release presentation only. The runtime changes below were already present
in earlier builds; they were not implemented by the release-formatting PR.

## New

- Persistent keepalive ranges let a peer vary its interval instead of using a
  fixed cadence. Rust, C and UAPI callers can configure and read the range.
- Rust callers can receive a packet with its full source endpoint and inspect
  acceptance metadata. Endpoint roaming must still require peer authentication
  and a successful action; acceptance alone is insufficient.

## Fixed

- Peer replacement detaches the old endpoint and its connected socket, so stale
  registrations do not retain the replaced peer. Reclamation is asynchronous;
  replacement is not guaranteed to preserve every in-flight packet. ([#111](https://github.com/Wiresock-Foundation/wiresock-boringtun/pull/111))
- Slow ordinary UAPI clients no longer block packet handling. Requests are
  framed, bounded by deadlines and support pipelining; ordinary client failures
  stay isolated. ([#112](https://github.com/Wiresock-Foundation/wiresock-boringtun/pull/112))
- Timer, queue and packet-validation fixes improve keepalive behavior, reject
  malformed IPv4 lengths and report a full pending-packet queue explicitly.
  See the source changelog for the detailed accumulated changes.

## Security

- Linux sockets prevent a different UID from sharing their UDP port. Same-UID
  sharing remains possible. Startup prepares TUN/UAPI before dropping privileges
  and creates UDP sockets and workers under the final UID. ([#113](https://github.com/Wiresock-Foundation/wiresock-boringtun/pull/113))
- Cookie replies no longer move peer endpoints. Replay, nonce-limit and
  source-aware handshake rate-limit checks strengthen handling of hostile traffic.

## Compatibility & upgrade notes

- **Rust API:** `WireGuardError::PacketQueueFull` requires an extra arm in
  exhaustive matches. Existing discriminants 0–16 retain their values; C/JNI
  receive code 17 through the existing error result without an ABI layout change.
- An inherited UAPI transport failure is fatal and requires a supervisor restart.
  Ordinary connected UAPI clients remain isolated from each other.
- Linux `fwmark` applies to sockets created or updated while the required
  privilege is available. The documentation clarifies that contract; it does
  not add a fail-closed startup guarantee. ([#114](https://github.com/Wiresock-Foundation/wiresock-boringtun/pull/114))
- Technical tags, archive naming, signed `RELEASE.json`, checksums and the seven
  release assets retain their existing format. Installers pinned to an earlier
  tag remain pinned until their maintainers explicitly adopt a new one.
- Versions now advance by an explicit reviewed `patch` or `minor` choice.
  Documentation/tests-only PRs can select `none` and create no release.
